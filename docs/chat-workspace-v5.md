# 对话工作区 v5

Samaya 采用可收起任务侧栏、连续对话和一体输入框。任务监控仍覆盖受管任务，不随最近列表数量或侧栏显隐停止。普通结束任务采用 36px 单行；运行、待处理、异常、后台活动采用 56px 双行，行间距 4px。侧栏虚拟列表按实际行高定位，状态刷新不重新排序最近任务。

## 输入与命令

斜线命令仅在输入第一个字符为 `/` 时识别并展示候选；前置空格、制表符、换行或正文里的 `/fork` 等内容均作为普通文本原样提交。`/fork` 沿用原生空闲轮次检查，运行中拒绝时在页面内显示原因，不弹窗、不排队。

- Enter 发送，Shift+Enter 换行。中文输入法确认不发送。候选打开时，方向键移动，Enter / Tab 选择，Esc 收起。
- `$` 浏览技能和应用；`/` 浏览命令、技能及用户自定义 prompts。正文里的金额、代码块、路径不会触发对应菜单。未知命令必须明确选择按普通文本发送。
- 技能使用 Codex `skills/list`，应用使用 `app/list`。选择引用后提交原生 `skill` / `mention` 输入，包含名称和路径；同名技能按来源选择。切换工作目录、移除文本或目录能力变化后重新校验，禁止把失效引用当成成功调用。
- 新建与当前任务共用输入组件。运行中追加到实际轮次；空闲时开启下一轮。轮次变化拒绝旧操作，不隐式排队。草稿和引用保存在当前浏览器会话中。
- “产物与记录”按需打开，当前工作区内切换页签保留阅读位置；重新进入对话定位到最新尾部。持续目标存在时在输入区显示状态、目标和 Token 用量。

## 能力边界

命令清单的代码真源是 `src/samaya/composer/commands.py`；菜单保留不可用项并解释原因。后端不提供任意 RPC 或 shell 透传。

| 入口 | 当前行为 |
| --- | --- |
| `/model`、`/reasoning`、`/fast`、`/plan` | 读取当前 daemon 的真实选项，确认后更新会话设置，影响后续轮次 |
| `/permissions`、`/memories` | 选择可用权限配置或会话记忆模式；执行时再次校验选项 |

| `/review` | 原生审查未提交改动、基础分支或指定提交 |

| `/new`、`/resume`、`/project`、`/local`、`/theme` | 打开已有的新任务、搜索、工作区、设置界面 |
| `/skills`、`/apps`、`/init`、`/copy`、`/agent`、`/subagents` | 浏览能力、生成可检查的项目说明草稿、复制回复、查看关联子任务 |

| 云执行、IDE、宠物、worktree、文件附件、终端专属配置 | 当前浏览器工作台未接入，显示具体说明 |

## 按工作区展开的任务总览（2026-10-04）

总览按完整工作目录 `cwd` 分组，同名但不同路径的工作区不会合并。所有当前范围内的工作区默认展开，可点击工作区标题独立折叠、展开，键盘 Enter/Space 同样可用；折叠后保留工作区名称、路径、任务总数、待处理任务数与最近活动。每组默认显示 5 个主任务；“再展开”每次增加最多 5 个，也可收起回 5 个。折叠整个工作区不会重置已展开的数量。子任务仍通过主任务关联活动查看。

待处理任务在所属工作区顶部以细边框标出，包括子任务关联请求和请求内容待恢复的状态，不再重复展示独立的待处理预览。其余任务按原生 `thread.recencyAt` 降序排列，缺失时使用 `updatedAt`，同时间戳采用稳定键排序。工作区按未经过状态筛选的主任务最近互动时间排序，运行日志和任务结束不会改变顺序。结束、中断和失败只更新任务状态，不再移入单独的“最近结束”折叠区。默认全部状态可持续观察变化，显式项目和状态筛选仍限定可见范围。全局待处理入口保留；展示范围不影响后台监控。

Figma 第 07 页的全部范围、项目选择、项目已选和状态选择均同步双主题分组布局，并补充 [展开更多 · 白垣](https://www.figma.com/design/TZOGfIsv1ESAQckxwg4lpa?node-id=91-6466) 与 [展开更多 · 苍渊](https://www.figma.com/design/TZOGfIsv1ESAQckxwg4lpa?node-id=91-6742)。标题顶部留白 24px，任务行左右留白 16px。页面标题、筛选栏和“最近活跃的工作区”标题固定，仅下方工作区列表局部滚动；6px 主题滚动条紧邻列表右侧，内容不足一屏时由浏览器隐藏，工作区折叠及加载更多后自动更新滑块比例。

## 最新内容优先与连续历史（2026-10-08）

每次进入对话默认定位到最末尾，先显示最新轮次；监控已知轮次 ID 时，内容请求与目录请求并行。首次目录只请求 1 个轮次，每页条目请求上限 100 条。向上滚动到距已载入内容顶部 240px 内自动补入历史，轮次和条目分页共用一个加载入口：先补齐较新轮次的记录，再按原生顺序接入更早轮次，每次接入 1 轮。工具密集或空页继续衔接，补入目标约为 2 个阅读视口，每批最多 6 次补页请求；达到上限后可继续上滚、按键或触摸向上阅读触发下一批。初始内容不足时自动补页，较长对话仍从最新尾部进入。已缓存的内容可直接复用。

正文不再显示两层分页按钮。加载时仅显示 24px 局部轻量提示；失败保留已读内容，暂停自动请求，在同一入口提供“重试”，继续使用失败游标。重复游标按异常停止，只有原生游标结束才显示“已到对话起点”。切换任务中止在途历史请求。向上补入时优先保持可见消息及其视口偏移，避免同时增长的实时尾部污染按高度差计算的补偿；原锚点消失时才回退高度差。

## /status 用量进度条

上下文和账号各额度窗口统一以剩余百分比绘制 4px 进度条（桌面最大宽度 440px，窄屏随容器收缩），同时显示剩余比例、状态文字和重置时间。仅显示左侧剩余比例，移除已用比例和状态文字。按剩余比例判色：高于 50% 使用浅绿，25%–50% 使用黄色，低于 25% 使用红色。沿用苍渊·白垣功能色，状态文字保持正文色。缺失用量显示“未提供”，不绘制零值进度条。累计 Token 与观察时间保留在下方，快照不冒充实时更新。

## 命令完成与输入清理

通过候选选择的命令（如 `/sta` → `/status`）在成功读取或执行后清除原命令草稿，包含会话内保存的草稿；不要求输入完整命令名。复制与导航成功后同样消费命令，技能／应用浏览入口清除命令前缀；`/init` 仍按设计填入待检查正文。取消、读取失败、命令不可用及执行未确认时保留输入，异步完成不会清除等待期间新写的草稿。普通答复成功不再在输入框上方显示“答复已发送／已确认”的全局提示；请求卡片继续反映服务端的处理状态，错误与未确认回执保持可见。

## 会话操作与命令历史

侧栏每条对话提供省略号按钮，悬停、聚焦、选中和触摸设备上可见；右键同一行打开同一份菜单，只有“重命名、归档、删除”。右键不会切换当前对话；点击菜单重命名直接在左侧对话标题处编辑，Enter 或失焦保存，Esc 取消；不切换对话、不占用消息输入框。`/rename` 仍在主输入框编辑。名字按字面处理，`/` 和 `!` 不会触发命令，也不会发送消息；保存失败保留名字和编辑状态。归档保留范围预览确认；菜单删除首次点击后原位变为“确定删除”，后台静默获取范围和摘要，第二次点击执行，失败留在菜单内。两者保留服务端范围校验与保护，运行中或有后台命令时仍拒绝清理。菜单支持方向键、Esc、点击外部关闭，滚动与窄屏下保持在可视区域。

成功执行的斜杠命令按完整命令名加入工作区本地输入历史，↑/↓可回溯，包括 `/sta` 补全后的 `/status`、查看命令及成功重命名后的 `/rename 名称`；失败或取消的命令不记录。离开会话或切换工作区时丢弃未执行的首字符为 `/` 的草稿，普通文字草稿继续保留；历史记录与临时草稿分别处理。

## 工作区管理

工作区标题旁新增省略号入口，进入 `/sessions?cwd=...`，刷新后保留当前工作区。页面使用独立的 `WorkspaceManagement` 组件，沿用任务总览的 1168px 外框、912px 主列、40px 筛选控件和 64px 对话行。服务端在分页前按工作目录精确筛选；只展示主会话，清理范围包含后代。支持搜索已加载对话、状态筛选、最近／最早活动排序、全选、批量归档、恢复归档和永久删除。路径只显示一次，长标题桌面一行、手机两行截断。全局记录管理保持原入口。

批量操作集中在列表上方的固定操作行。归档与恢复先静默核对范围再执行；删除在原位变为“确定删除 N 个”，可展开检查后代及其它目录的影响范围，不另弹窗口。确认期间锁定筛选和选择，取消不执行操作。范围读取最多并行四项，写操作逐项执行；结果收成一行摘要，失败原因可展开，失败条目保留。失败或结果待确认不会自动重发。列表具有独立滚动区和稳定的滚动条占位，避免长记录把确认按钮推到页底。归档成功的条目立即退出侧栏与任务总览；部分失败只移除已核实成功的范围，恢复归档后重新核对显示。执行中或仍有后台命令的会话继续由服务端拒绝清理。

## 执行计划展示

原生 `plan` 条目默认展开，直接显示 Markdown 正文；用户仍可手动收起。计划不归入工具日志折叠组，在“对话”和“改动与产物”两页都可阅读。

计划正文直接消费原生 `item/plan/delta`，按 thread、turn、item 身份及 SSE 序号合并，约每 250ms 更新 Markdown，不等待轮次完成。重连核对保留当前已观察到的计划片段；`item/completed` 原位替换为完整计划，迟到增量及旧分页响应不能追加或覆盖已完成内容。若未收到条目完成事件，轮次结束后的完整历史读取会替换临时计划。用户手动收起的选择在增量更新期间保留。回归入口：`tests/plan-output.mjs`。

## 发送回执与草稿恢复

“轮次已结束”与“浏览器已收到发送结果”独立判断。此前一次响应丢失会留下本地回执，并被当作整个输入框的忙碌状态，导致已经完成的会话仍不能编辑。现在发送中或等待回执期间可以继续编辑草稿，发送和停止操作仍保留按对象去重的保护。

页面消费 `samaya/operation` 的终态回执，并在载入、网络恢复、重新聚焦及定时核对时查询原操作 ID。仅明确 `succeeded`／`failed` 才清除阻塞；`pending`、`uncertain`、404 和网络失败继续保留待核查状态，不自动重发。服务端事件先确认时直接结束客户端等待；POST 等待上限 30 秒，不取消服务端已有任务。跨页 Web Lock 不再无限排队。

回执恢复不清空用户后来编辑的内容；真实失败显示原失败原因，成功恢复移除过期的“结果待确认”提示。回归入口为 `tests/receipt-recovery.mjs`，纳入 `test:monitor`。
