## 实际实现与数据来源

首页现在是紧凑任务列表。跨项目搜索与筛选、全局待处理和异常入口、置顶、按需详情、专注阅读与最近变化保持在同一应用壳层。对话、结果和执行记录是详情中的次级入口。新建目标和当前任务草稿有明确归属。

任务直接使用 Codex `Thread` 身份。父子关系来自 `parentThreadId` 或 `source.subAgent.thread_spawn.parent_thread_id`，顶级任务计数不重复计入子任务。父会话不可见的子会话仍标为子任务，不能据此构造虚假的父任务。项目范围使用原生 `cwd`，导航不会修改它。

`codex/monitor.py` 仅在内存中缓存官方线程、最近轮次、最近 12 条条目摘要及后台命令。每条摘要的长文本最多 2,000 字符，完整记录通过官方分页按需读取。`confirmedAt` 是 Samaya 观察时间；`progressAt` 优先使用原生条目 / 轮次时间，缺少原生时间时仅在观察到新的活动后记录观察时间。AI 回复始终标为“AI 说明”，不推断测试通过、完成率或目标达成。

仍使用 `openai-codex==0.160.0` 与已有 0.160.0 daemon。SDK 私有传输边界只在 `adapter.py`。`turn/steer` 通过 SDK 已有的低层异步客户端方法调用，并校验 `expectedTurnId`。没有加入服务端队列；输入区草稿不表示排队。

### 状态契约

| 维度 / 来源 | 页面含义与恢复 |
| --- | --- |
| `Thread.status.active` / 当前 `Turn.inProgress` | 执行中；不等于有新的有效进展 |
| `Turn.completed` | 本轮结束；不宣布目标完成，继续显示后台 / 子任务活动 |
| `Turn.interrupted` | 本轮中断；更具体原因仅在服务端提供时展示 |
| `Turn.failed`、原生错误 | 失败及错误说明；没有错误说明时明确缺失 |
| 没有轮次 | 尚无执行轮次；不猜测已经排队 |
| 未映射状态 | 保留原生值并显示待确认，不归为成功 |
| 原生请求对象 | 单独统计请求和所属任务；选择、补充、审批、MCP 使用共享表单 |
| 等待标志但无请求正文 / 断线遗留请求 | 内容待恢复；不构造可授权表单，不计为“没有待办” |
| 桥接答复回执 `{sent:true}` | 仅证明已发送；保留禁用的待确认请求，直到原生 resolved / 适用的轮次结束事件 |
| 原生请求已消除 | 不再允许回答；与任务是否继续执行分开确认 |
| 停止请求已回执、本轮仍运行 | 停止请求处理中；不暗示进程全部结束或文件回滚 |
| 连接丢失、快照缺口或单项读取失败 | 保留最后状态与时间，显示待恢复 / 待确认 |
| 目录切换 | 单独操作；执行中要求先等结束或明确停止；由服务端确认 cwd |

### 最小接口增量

- `GET /api/monitor`：原生记录及观察元数据、连接代次、汇总版本、请求集合、当前进程的最近变化。
- `GET /api/threads/{id}/turns`：官方轮次分页。
- `GET /api/threads/{id}/turns/{turn}/items`：官方条目分页，返回本地事件游标。
- 原有 `/api/events` 新增 `event: monitor`，传输内存中的版本化增量；授权正文与 URL 不写入该增量。版本缺口或代次变化触发快照核对。
- 原有 `/api/operations` 增加 `steer`；其他操作与回执契约复用。

目录扫描与线程列表约每 30 秒核对；所有已加载线程及后台命令约每 5 秒核对。并发读取上限 4，实际间隔还取决于服务响应和队列耗时。关键事件触发优先核对，汇总更新以 250 ms 合并。浏览器筛选、虚拟化、详情开关不改变后端观察范围。订阅只加入已经加载的会话，不为监控加载所有旧会话进入运行时。

增量保留最近 64 批，属于可丢弃的内存缓存，不写入任务表。重复 / 旧版本增量不覆盖新版本；旧轮次开始事件不能复活已结束轮次。RPC 读取期间如果出现更新，旧读取结果被丢弃。客户端拿到关键增量后的呈现延迟与服务端发现变化的延迟分别评估。

操作身份在发送前写入浏览器，按请求 / 会话限定待核查范围，跨标签页优先使用 Web Locks，服务端继续校验原生轮次和请求身份。网络错误及 HTTP 5xx 保留待核查回执，刷新不重发。旧版 `samaya.pending` 会迁移。`create` 成功而后续发送未确认时，保留新会话身份与目标草稿。

## 尚未验证与限制

- 本次没有向已有真实任务提交追加、审批、停止或清理，也没有为 UI 重派真实任务。这些写路径使用协议 / 浏览器夹具验证；先前 v1 的真实执行验收记录仍见 `verification.md`，不能等同于本次新版全流程实测。新增 `turn/steer` 的真实执行结果尚未验证。
- app-server 没有已验证的完整待请求枚举 / 重放接口。Python 连接断开前未收到的表单不能保证恢复；等待标识与未知提示保留。桥接 `sent` 不能当成服务端决定已生效；旧流程未提供 resolved 时保留待确认提示，不以执行继续代替请求确认。
- 最近变化保留当前 Python 进程最近 100 项；Python 重启后不恢复完整变化摘要。执行状态仍重新读取 Codex，不重发任务。
- 没有可靠排队能力、目标完成判定、自动验收、外部通知、附件上传或 Git 全目录撤销。测试结果展示来源记录，不从日志内容自动推断统一通过率。
- 活动轮次的流式片段与恢复记录分别标识；断线期间的增量可能丢失，周期性读取和完成事件恢复正文。长条目本身仍可能较大；只有线程列表做虚拟化，没有声称无限日志容量。
- 搜索覆盖汇总中的任务名、目录及最近进展，不是所有历史消息的全文检索。归档管理使用分页记录，页面明确显示已加载数量。
- 桌面 Chromium 和窄视口已测；真实 iOS / Android 软键盘、屏幕阅读器人工走查及第三方 OAuth 未在本轮实测。
