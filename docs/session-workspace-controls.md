# 会话控制与工作区导航验收

分支：`feature/session-workspace-controls`。

## 设计

继续使用现有 MANAS 工作区结构和苍渊·白垣双主题。

- [对话工作区：工作区导航与内联状态](https://www.figma.com/design/TZOGfIsv1ESAQckxwg4lpa?node-id=276-5045)
- [任务总览：折叠工作区的运行提示](https://www.figma.com/design/TZOGfIsv1ESAQckxwg4lpa?node-id=5-749)

侧栏工作区可折叠，显示未归档主会话，每次展开 10 条，直接进入会话并提供新建入口。移除独立的“查看全部任务”页面和状态恢复分支。总览保留工作区分组、筛选、展开、置顶、待处理和记录管理。

工作区运行数量从完整观察集聚合，按正在执行的主会话及子智能体计数，同一主任务只计一次，不受当前列表筛选或折叠影响；仅残留后台命令不触发运行高亮。失联、观察过期不继续伪装为确定运行状态。

## 模型与状态

- 新会话通过 `config/read(cwd)` 和分页 `model/list` 读取当前目录默认值，可在发送前选择模型、强度及 Fast。创建时重新验证支持档位，并将参数传入 `thread/start`。
- `Alt+,` 降低、`Alt+.` 提高思考强度；限定当前输入器，不循环、不抢光标、不展示常驻快捷键提示。已有会话使用原生 `thread/settings/update`。
- `/status` 在原对话位置立即显示本地快照，异步读取配置、用量和限额，不创建模型轮次。浏览器页签保存快照，后端保存最新 `thread/tokenUsage/updated` 观察及时间。旧数据标注观察时间，缺失字段明确显示未提供。
- SDK 和其 CLI 包固定升级为 `0.163.0`；实际连接现有 daemon，未启动替代执行实例。

## 首次发送排查

升级前后的真实 `thread/start → turn/start` 均成功；显式选择模型的创建也成功。没有证据将用户遇到的偶发失败归因于 SDK 本身。

确认并修复了前端恢复问题：创建成功后发送失败，原来的 `open(id)` 会清空刚写入的错误与提示。现在保留具体错误和恢复说明，将文字、引用和附件转到已创建会话，不要求重新创建；整个创建流程加锁，避免两阶段操作之间重复触发。模型设置未读取或未确认时不抢先发送。后端操作日志包含操作类型、操作编号、会话编号及结果，不记录消息正文。

用量通知只覆盖服务观察到的会话，不从 Codex 私有数据库或日志推算历史 Token。没有通知的历史会话会显示未提供。快照保留在当前页签，不写入模型会话历史。

## 工作区搜索与执行高亮修正

任务总览常驻显示工作区搜索框，按名称或路径实时过滤，忽略大小写和首尾空格；项目、状态筛选使用统一高度的描边控件。输入工作区名称时清除旧项目与状态筛选，从全部工作区查找；从全局搜索打开工作区同样清除旧搜索条件，避免有记录却显示空列表。窄屏搜索框独占一行。

总览与侧栏的工作区高亮仅计入近期确认、正在执行轮次的对话。等待用户输入或授权、有待处理请求、已经结束、仅残留后台终端、断线或过期状态均不触发高亮；子智能体仍按根对话去重计数。Figma 任务总览的双主题筛选栏已同步。

回归入口：`pnpm --dir src/web run test:scope`（包含搜索、等待/结束不高亮及窄屏专项）与 `tests/session-controls.mjs`。
