# 浏览器延迟修复验收（2026-10-27）

## 测量边界

服务为真实 HTTPS 8765，约 747 个原生会话；浏览器在服务器本机运行。生产探针只允许 GET/HEAD，不发送提示词、不改变模型或审批任务。另以 Chromium 模拟 20 Mbps 带宽和 20 ms 延迟，不能将其当作用户电脑的实际局域网结果。

修复前后都有后台任务与其他浏览器在线，因此事件量随时间变化。下列流量注明观察时长，不用不等长样本计算精确提升倍数。结果见 [results.json](results.json)。

## 结果

| 测量项 | 修复前 | 修复后 |
|---|---|---|
| 总览响应体 | 约 14 MB | 约 1.58 MB |
| 本机总览接口 | 串行样本约 555～653 ms | 20 次采样 P50 81 ms、P95 106 ms |
| 本机状态接口 | 与总览并发时约 450 ms | 20 次采样 P95 7 ms |
| 本机模型设置读取 | 样本约 48～828 ms | 20 次采样 P95 48 ms |
| 浏览器事件流 | 打开总览再进入对话，49 秒约 551 MB | 直接进入对话，16 秒约 0.55 MB；完整应用目录事件为 0 |
| 首次对话总览请求 | 初始化与回放反复触发 | 本机与限速场景均为 1 次 |
| 菜单自动化点击 | 曾等待约 4.9 秒；原生点击事件排队约 394 ms | 本机 5 次 P95 73 ms；限速场景 67 ms |
| 输入到下一帧 | 未采集同口径基线 | 两个场景 30 次输入样本 P95 约 13 ms |
| 浏览器主线程长任务 | 对话约 34 秒内 98 次、合计 18.9 秒 | 本机约 16 秒内 3 次、合计 208 ms |

点击耗时包含 Playwright 等待元素可操作的时间，不能等同于纯事件处理时间。限速场景的总览完整下载约 751 ms，主要受约 1.58 MB 响应的传输时间影响；菜单与输入在数据加载后保持流畅。

应用目录有约 5,100 个条目。首次读取与首次目录失效后再读取仍约 8～9 秒；连续缓存读取约 113～117 ms。缓存有效期 30 秒，目录实际变化会失效。这部分原生目录冷加载开销尚未消除，但不会锁住普通文本输入、发送或模型菜单。此次没有改变原生 app/list 分页协议。

## 修复和正确性验证

- 首次 SSE 从当前游标开始，全局与当前对话按范围订阅；断线继续使用游标，过期则重新读取快照。全局完成事件只携带轮次标识和状态。
- 应用目录事件仅保留轻量变更通知。旧目录事件分批转换，保留事件 ID，不删除原生会话、授权或操作记录；没有在线执行 VACUUM。
- 总览与补丁均使用字段白名单和文本预算，移除图片、原始工具返回与嵌套长内容。历史接口仍提供完整正文，`/copy` 从完整历史读取。
- 技能、应用缓存独立失效，并发查询共享读取；取消单个浏览器请求不会取消其他等待者。相同目录通知不反复失效，失效期间完成的旧读取不会写回缓存。
- 总览已是 JSON 原生结构，直接构造 JSONResponse，避免重复递归转换。
- 后端全量测试通过；浏览器通过计划流式输出、计划完成选项、授权交互、模型选择、回执恢复和直接停止回归；Lint、类型检查和生产构建通过。

原生 Codex daemon 未重启。Samaya 保持 8765；部署前核对没有未完成的操作回执与待处理授权。测试未向现有会话提交任何消息。
